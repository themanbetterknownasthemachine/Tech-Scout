Grundlagen

Skill vs. Agent

Zwei Komponenten bilden das Fundament des Systems. Beide erfüllen eine klar definierte, unterschiedliche Rolle.

📋 Skill

Das Gehirn des Systems. Eine Markdown-Datei (SKILL.md) mit vollständigem Wissen: alle Quellen, Qualitätskriterien, Red Flags, Thought Leaders und den 9-Schritt-Workflow.

→

Tut selbst nichts — muss von jemandem ausgeführt werden.

🤖 Agent

Der Ausführer. Ein Python-Script das den Skill liest, ihn als System-Prompt an die Anthropic API übergibt, Web Search ausführt und die Ergebnisse als JSON speichert.

→

Code der handelt — liest den Skill und wendet ihn an.

🔄 Agentic Loop

Web Search ist kein einfacher API-Call. Der Agent führt einen Loop aus: API antwortet mit tool_use → Agent schickt Result zurück → bis end_turn.

→

Ermöglicht echte Echtzeit-Websuche mit aktuellen Resultaten.

Einrichtung

Setup Schritt für Schritt

Einmalige Einrichtung — danach läuft alles vollautomatisch.

1

GitHub Repository erstellen

Ein neues Repository auf github.com anlegen. Der Name wird Teil der Website-URL. Public Repository — GitHub Pages ist damit kostenlos verfügbar.

github.com → New repository → Name: "Tech-Scout" → Public → Create
github.comPublic Repo
2

Anthropic API Key erstellen

Auf der Anthropic Console einen neuen API Key für den Tech Scout erstellen. Der Key wird nur einmal angezeigt — sofort kopieren.

console.anthropic.com → API Keys → + Create Key Name: "tech-scout" → Key kopieren (sk-ant-...)
console.anthropic.comAPI KeyCredits kaufen
3

API Key als GitHub Secret hinterlegen

Der API Key wird sicher als verschlüsseltes Secret im Repo gespeichert — nie im Code selbst. GitHub Actions kann ihn lesen, niemand sonst.

Repo → Settings → Secrets and variables → Actions → New repository secret Name: ANTHROPIC_API_KEY Secret: sk-ant-... → Add secret
SettingsSecretsEncrypted
4

Dateien ins Repository hochladen

Die Repo-Struktur aufbauen. Alle 6 Dateien können per Drag & Drop in GitHub hochgeladen werden. Den Unterordner .github/workflows/ direkt in GitHub via "Create new file" anlegen.

# Repo-Struktur Tech-Scout/ ├── tech_scout_agent.py # Python Agent ├── SKILL.md # Tech Scout Skill ├── index.html # Website (GitHub Pages) ├── README.md # Dokumentation ├── .gitignore # Ausschlüsse └── .github/workflows/ └── tech_scout.yml # Automatisierung
UploadDrag & Drop6 Dateien
5

GitHub Pages aktivieren

Mit einem Klick wird das Repository als Website veröffentlicht. Die URL basiert auf dem GitHub-Username und Repo-Namen.

Repo → Settings → Pages Source: Deploy from a branch Branch: main / root → Save # Website live unter: https://username.github.io/Tech-Scout

Einmalig manuell testen

Vor dem ersten Montag einmal manuell triggern um sicherzustellen dass alles korrekt eingerichtet ist. Der Run dauert ca. 3-5 Minuten.

Repo → Actions → Tech Scout Weekly → Run workflow → Limit: 5 → Run workflow # Erwartetes Ergebnis im Log: ✓ SKILL.md geladen (7282 Zeichen) ✓ Scout-Workflow abgeschlossen ✓ 5 Findings strukturiert ✓ findings.json erstellt

Betrieb

Wöchentlicher Workflow

Nach dem einmaligen Setup läuft alles vollautomatisch. Die einzige Aktion: Website öffnen.

Montag · 08:00 Uhr
GitHub Actions startet automatisch
Der Cron-Job 0 7 * * 1 (UTC = 08:00 CH) triggert den Workflow ohne manuellen Eingriff.
08:00 – 08:01
Agent liest SKILL.md
Das Python Script lädt SKILL.md vom Repo und übergibt den Inhalt als System-Prompt — mit allen Quellen, Qualitätskriterien und dem 9-Schritt-Workflow.
08:01 – 08:03
Web Search via Agentic Loop
Claude Sonnet sucht auf arXiv, HuggingFace, GitHub Trending, Firmen-Blogs (Anthropic, OpenAI, DeepMind, Meta, Snowflake, dbt) und Community-Quellen nach den aktuellsten Findings.
08:03 – 08:05
JSON Strukturierung & Speichern
Ein zweiter API-Call (Claude Haiku) strukturiert die Findings als JSON. Deduplication via MD5-Hash verhindert Duplikate. Die Datei wird ins Repo committet.
Jederzeit danach
Website öffnen — fertig
Die Website lädt tech_scout_findings.json direkt von GitHub via Raw-URL. Keine Installation, kein Import — einfach den Browser-Favoriten öffnen.

Automatisierung

Wie GitHub Actions funktioniert

GitHub Actions ist ein kostenloser CI/CD-Dienst direkt in GitHub — kein externer Server nötig.

🖥️ Was ist GitHub Actions?

Ein virtueller Ubuntu-Server der von GitHub bereitgestellt wird. Er startet auf Befehl, führt beliebige Befehle aus und wird danach wieder gelöscht. Kostenlos für Public Repositories.

Analogie

Wie ein Mitarbeiter der jeden Montag morgen ins Büro kommt, eine Aufgabe erledigt und danach wieder geht.

📅 Trigger: Wann startet es?

Der Workflow wird durch einen Cron-Schedule gestartet — eine Unix-Zeitangabe die definiert wann der Job läuft.

Unser Schedule
cron: "0 7 * * 1"
# Min Std Tag Monat Wochentag
# 0 7 * * 1 = Montag 07:00 UTC = 08:00 CH

🔐 Secrets: API Key sicher?

Der API Key wird als verschlüsseltes Secret gespeichert — nie im Code. GitHub entschlüsselt ihn erst beim Ausführen und gibt ihn als Umgebungsvariable weiter.

Sicherheit

Niemand kann den Key lesen — auch nicht der Repo-Owner. Er wird nur zur Laufzeit injiziert.

Ablauf eines Runs — Schritt für Schritt
⏰
Trigger
Montag 08:00 Uhr (Schweizer Zeit) — GitHub startet automatisch einen frischen Ubuntu-Server.
📥
Checkout Repository
Der Server lädt alle Repo-Dateien herunter — inkl. tech_scout_agent.py und SKILL.md.
🐍
Python Setup & Dependencies
Python 3.12 wird installiert, dann pip install anthropic ausgeführt.
🔭
Tech Scout ausführen
Der Agent liest SKILL.md, ruft die Anthropic API auf, führt Web Search durch und speichert tech_scout_findings.json. Der API Key wird aus den Secrets als Umgebungsvariable injiziert.
📊
Output prüfen
Der Workflow prüft ob findings.json erstellt wurde. Falls nicht → Fehler-Meldung im Log, kein Commit.
💾
Commit & Push ins Repo
Die aktualisierte findings.json wird automatisch committet. Die Website liest sie beim nächsten Öffnen direkt von GitHub.
Das YML File erklärt
# Wann soll der Workflow starten?
on:
  schedule:
    - cron: "0 7 * * 1"  # Jeden Montag 08:00 CH
  workflow_dispatch:  # Auch manuell startbar

# Was soll ausgeführt werden?
jobs:
  scout:
    runs-on: ubuntu-latest  # Frischer Ubuntu-Server
    permissions:
      contents: write  # Darf ins Repo committen

    steps:
      - name: Python Setup
        uses: actions/setup-python@v5

      - name: Tech Scout ausführen
        run: python tech_scout_agent.py
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}  # Secret wird injiziert
